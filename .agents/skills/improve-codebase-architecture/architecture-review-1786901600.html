1 · Promote TimeRange to a real type

Strong

Files: internal/openobserve/{logs,traces,metrics}.go, internal/mcp/tools.go

Concept (proposed): TimeRange — a paired (start, end) window with a default constructor. Carries WHERE-clause fragments too.

Problem. StartTime / EndTime / Limit travel together through every request struct and default identically in every method (logs.go:38–52, logs.go:153–158, traces.go:36–44, metrics.go:35–43). The timestamp >= / <= WHERE pair is rebuilt verbatim at four sites. The duplication means a change to default-window policy (e.g. "last 1h" → "last 15m") is a four-file edit. Tests can't pin the default behaviour through a single fakeable surface.

Solution. Introduce a TimeRange type with:

  • NowRange(d time.Duration) TimeRange — the policy today lives here, one place.
  • Where() []string — emits the two timestamp >= / timestamp <= fragments.
  • Replace three loose fields per request with a single TimeRange, defaulting at the request boundary.

Benefits. Locality: window policy sits in one place; the SQL builder doesn't need to know what "default" means. Leverage: every method becomes shorter by ~10 lines. The interface is the test surface: fake TimeRange in tests and the SQL builder becomes trivially testable.

Before

type SearchLogsRequest struct {
    Stream  string
    Level   string
    StartTime time.Time
    EndTime   time.Time
    Limit     int
}

func (c *Client) SearchLogs(ctx, req) ... {
    if req.StartTime.IsZero() { req.StartTime = time.Now().Add(-1*time.Hour) }
    if req.EndTime.IsZero()   { req.EndTime   = time.Now() }
    ...
    where := []string{
        fmt.Sprintf("timestamp >= %d", req.StartTime.UnixMicro()),
        fmt.Sprintf("timestamp <= %d", req.EndTime.UnixMicro()),
    }

After

type TimeRange struct{ Start, End time.Time }

func NowRange(d time.Duration) TimeRange { /* one place */ }
func (r TimeRange) Where() []string {
    return []string{
        fmt.Sprintf("timestamp >= %d", r.Start.UnixMicro()),
        fmt.Sprintf("timestamp <= %d", r.End.UnixMicro()),
    }
}

type SearchLogsRequest struct {
    Stream string
    Level  string
    Range  TimeRange
    Limit  int
}

func (c *Client) SearchLogs(ctx, req) ... {
    where := append(req.Range.Where(), /* filters */)

2 · Single normalization point on Client

Strong

Files: internal/openobserve/{client,logs,traces,metrics}.go

Concept (proposed): StreamKind — typed enum of Log/Metric/Trace, each owning its default stream name.

Problem. if req.Stream == "" { req.Stream = "<default>" } recurs eight times across three files, defaulting to one of three string literals ("default" / "traces" / "metrics") that are also duplicated as bare strings. The schema-discovery path in logs.go even has a fourth call-site where the default "default" hides inside a fallback branch.

Solution. A StreamKind enum on the request side, with each method on Client resolving it via a single helper defaultStream(StreamKind) string keyed on a config map. The default-stream-per-kind is data, not code.

Before

// logs.go, traces.go, metrics.go — same shape repeated
if req.Stream == "" {
    req.Stream = "default"   // or "traces" / "metrics"
}
if req.Limit <= 0 {
    req.Limit = 100
}
if req.Direction == "" {
    req.Direction = "desc"
}

After

type StreamKind int
const ( Log StreamKind = iota; Metric; Trace )

type Client struct { ...; defaultStreams map[StreamKind]string }

func (c *Client) SearchLogs(ctx, req) ... {
    req.Stream = c.resolveStream(Log, req.Stream)
    req.normalize()
    ...
}

Benefits. Locality: the three default-stream literals live once on the client (or in config), not seven times in three files. Leverage: a future change "metrics now go to app_metrics" is a one-line edit. The interface is the test surface: a fake Client with a fixed default-stream map catches any caller that bypasses normalization.

3 · Extract an HTTP seam so the adapter is testable

Strong

Files: internal/openobserve/client.go (entry), tests under internal/openobserve/*_test.go

Concept (proposed): Transport — a single-method interface that the Client delegates the actual HTTP call to.

Problem. client.go:61–102 (do()) holds the marshalling, auth, body-cap, status-classification, JSON decode — all genuinely valuable behaviour. But c.http is a concrete *http.Client (client.go:22, 50, 79) with no interface above it, so the entire layer is untested: there are zero *_test.go files in internal/openobserve/. The schema cache is the only piece testable in isolation today, and it's not tested.

Solution. Extract a Transport interface (one method: Do(req *http.Request) (*http.Response, error)) and have Client hold a Transport. A test fakeTransport returns canned *http.Responses. Result: every public method (SearchLogs, AggregateLogs, QueryMetrics, SearchTraces) becomes unit-testable with no network. The existing http.Client still implements the interface zero-cost.

Before

type Client struct {
    http *http.Client    // concrete; cannot be faked
    ...
}

func (c *Client) do(...) {
    resp, err := c.http.Do(req)   // <-- only place a test could intercept
    ...
}

After

type Transport interface {
    Do(*http.Request) (*http.Response, error)
}

type Client struct {
    transport Transport   // *http.Client satisfies it
    ...
}

func NewClient(cfg *config.Config) *Client { return &Client{transport: &http.Client{Timeout: cfg.Timeout}, ...} }

// in tests:
type fakeTransport struct{ resp *http.Response; err error }
func (f *fakeTransport) Do(*http.Request) (*http.Response, error) { return f.resp, f.err }

Benefits. One adapter = hypothetical seam, two adapters = real — the test fake is the second adapter, so this is unambiguously a real seam. Deletion test: deleting the concrete *http.Client field concentrates complexity in Transport, which is the signal we want. Tests at this seam catch SQL-builder regressions without a running OpenObserve.

4 · Move SQL building out of the adapter

Worth exploring

Files: internal/openobserve/{logs,traces,metrics}.go → propose moving SQL into a sibling sqlbuilder/

Concept (proposed): SQLBuilder — a small package per kind that takes a request and returns a parameterised SQL string + args.

Problem. traces.go (120 lines) and metrics.go (110 lines) are mostly request-normalization + string-formatted SQL + envelope construction + a single c.do() call. The actual transport is one line in each. The interface is small but the methods are almost entirely "format a SQL string." This is shallow module territory: interface nearly as complex as the implementation.

Solution. A sqlbuilder/ package with one file per kind (logs.go, traces.go, metrics.go) that exports Build(req) (string, []any, error). The adapter's adapter methods become delegate-and-call: build, encode, post, decode. The schema-driven column picker moves with the SQL building — it's not a transport concern.

Before

// traces.go
func (c *Client) SearchTraces(ctx, req) ... {
    // ... 50 lines of normalize + WHERE-build +
    // ... SQL format + envelope + c.do() ...
}

After

func (c *Client) SearchTraces(ctx, req) ... {
    sql, args, err := sqlbuilder.Traces.Build(req)
    if err != nil { return nil, err }
    var resp SearchTracesResponse
    return &resp, c.search(ctx, sql, args, &resp)
}

Benefits. Locality: SQL dialect knowledge lives in one place per kind, swappable when the underlying store changes. Leverage: each builder is independently testable with no Client needed. The adapter methods become genuinely thin, justifying their existence.

5 · Consolidate the _search envelope

Worth exploring

Files: internal/openobserve/client.go, refactor call sites

Concept (proposed): searchQuery — typed struct for the {"query": {...}} envelope.

Problem. The OpenObserve search envelope {"query":{"sql":...,"start_time":...,"end_time":...,"from":0,"size":...}} is rebuilt verbatim four times (logs.go:97–105, logs.go:172–180, traces.go:73–81, metrics.go:77–85). Same shape but with map[string]any, no type help, easy to drift.

Solution. A typed searchQuery struct (SQL string; StartTime, EndTime int64; From, Size int) and a single c.search(ctx, query, out) error helper that knows how to marshal and POST to /api/{org}/_search. JSON tags render start_time correctly.

Benefits. Locality: the wire shape lives in one place; future envelope changes are a one-file edit. Type-safety replaces map-soup.

6 · The "default = last 1h" policy is product-shaped

Speculative

Files: config plumbing into internal/config

Problem. Hard-coded time.Now().Add(-1*time.Hour) at logs.go:48, traces.go:40, metrics.go:39, logs.go:154. A real "default time range" is a UX/product choice baked into the adapter.

Solution. Add DEFAULT_QUERY_WINDOW to internal/config, use it inside TimeRange.NowRange from candidate 1. Conditional on candidate 1 — no point doing this twice.

Benefits. Configurable without code edits; one knob controls all four default windows at once.

Top recommendation

Tackle candidates 1, 2, and 3 together as one deepening. Each individually ranks "Strong"; together they form one coherent deepening of internal/openobserve/:

  • Candidate 3 first — the Transport seam unlocks testing for everything else. Without it, candidates 1, 2, 4, 5 are unverified refactors.
  • Candidate 1 next — TimeRange removes a high-impact clump and gives a natural home for the "default window" policy (candidate 6).
  • Candidate 2 last — StreamKind consolidation rides on the new test seam; behaviour is verifiable after the seam exists.

Together they collapse ~80 lines of duplication, make the adapter deep instead of wide, and convert a fully-untested package into one with HTTP-level unit tests. Candidates 4 and 5 become small, almost-mechanical follow-ups once the deep module exists.
